- 日期：2026-10-22
- 提案来源：用户转来的《字趣·甲骨构字记：产品与美术升级提案》
- 核对方式：在**当前工作区代码**里逐项查存在性；不按记忆，也不按提案的截图推断（提案本身说明它没看到源码）

## 一、一句话结论

提案要的是**产品重做**（视觉骨架 → 核心玩法 → 成长沉淀 → 沉浸表现），
现有实现是**在旧结构上做的表现层升级**。
两者不冲突，但提案里**四个大件**目前是空的：

1. 首页的「纵深 + 展览式三关入口」
2. 构字的「拖拽 / 吸附 / 刻痕亮起」
3. Boss 的「知识解谜型阶段机制」
4. 探索档案 + 龟宝成长记忆

## 五、我建议的落地顺序（结合提案优先级 + 谁能做）

**先做"能被看见"的，再做"要重写玩法"的。**

1. **首页纵深 + 删减首屏**（4h+1h）——见效最快，不动玩法
2. **三关入口展览化**（3h）——纯前端
3. **探索档案页（只读版）**（4h）——用现有 `achievements`/`atlas`/`reward` 数据拼，不新增玩法
4. **构字拖拽吸附**（6h）——真正动玩法，风险最高，放第四
5. Boss 知识机制、纪念卡、环境音——按剩余时间排

## 六、需要先定的三件事

1. **艺术方向**：提案的三层（考古/水墨/青铜）要不要照做？还是维持现在"骨白 + 朱砂"？
2. **知识边界**：提案要求"历史必须严谨"——字形/释读/演变都只能引用现有 `data.js` 与 CC BY 4.0 字形数据，**不能编**。这条我认同，会照做。
3. **谁做**：我（DSH）负责前端与交互，WorkBuddy 负责视觉令牌与版式，GPT 负责文案——提案里的"统一设计系统"需要三方对齐一次，否则又会各改各的。

## 七、我不建议现在做的

- 不要同时开工 4 个阶段（提案自己也这么说）
- 不要先做"收藏 / 纪念卡 / 分享"——依赖档案页
- 不要先做拖拽——它是唯一需要动玩法状态机的，容易把已验收的 P0/P1 打回
