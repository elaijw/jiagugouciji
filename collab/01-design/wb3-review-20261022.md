## 二、最要紧的一处：`.btn.danger` 用错了地方

全站只有三处用到 `danger` 这个类名：

```
js/modes/bone-build.js:869   'btn danger hidden'  → 文案「质问！」
js/modes/bone-build.js:1212  'btn danger'         → 文案「质问！」
boss-raid.js:1342            'btn sm ghost'       → 文案「清空通关记录」
wangyi-map.js:358            'wy2-reset'          → 文案「重置本关进度」
```

也就是说：

- **被标成"危险"的按钮，其实是第一关的核心动词「质问！」**——朱砂填朱，语义完全正确；
- **真正的破坏性操作（清空通关记录 / 重置本关进度）反而用的是最弱的样式**（`ghost` 和 10px 的裸描边），
  一个孩子点错就抹掉 21 关进度，只靠一句 `window.confirm` 兜。

按 TASK「同一操作类型只有一种样式」的原意，`danger` 应当表示**破坏性**。但类名已被玩法代码占用，
所以本轮的做法是**把两种语义拆开，而不是改玩法**：

| 类 | 语义 | 形态 | 使用者 |
|---|---|---|---|
| `.btn.primary` | 主操作 | 朱砂实底 + 受光三段 | 开始探索 / 开始第一课 / 挑战 Boss |
| `.btn` | 次操作 | 透明底 + 骨线 + 凹槽 | 上一关 / 下一关 / 继续 |
| `.btn.danger` | **强烈动作**（质问式） | 朱砂再压深一档，同族 | 质问！ |
| `.btn.destructive` | **破坏性** | 骨面 + 危险色描边，**悬停才填实** | 暂无（见下） |
| `.btn.ghost` | 弱操作 | 无底无框 | 清空记录 |

为什么破坏性要用「描边」而不是「更暗的实底」：白字压 `--solid #ae4936` 是 5.52，
压深一档的朱砂是 7.92——**两者在 390px 屏上只剩明度差**。读者以中小学生为主，
明度差会被读成"两个都很重要"。实底 ↔ 描边是结构差异，扫一眼就分得开。

**需要 DSH 改一行**（`js/` 归你）：`js/modes/boss-raid.js:1342`

```js
-  var clr = App.el('button', 'btn sm ghost', '清空通关记录');
+  var clr = App.el('button', 'btn sm destructive', '清空通关记录');
```

改完即生效，样式已经在 `ui.css` 里备好，不需要再动 CSS。

## 三、谁说了算：一枚按钮曾在四个文件里各写一遍

改之前，`.btn` / `.btn.primary` 的**最终外观**由 `<link>` 顺序决定，而不是由哪个文件"看起来像按钮表"决定：

```
app.css(1)  →  theme.css(2)  →  ui.css(3)  →  ……  →  atmos.css(10)  →  carved.css(33)
   .btn           .btn             .btn                  .btn            body.carved .btn
 深墨实底       骨面+发丝边     透明+凹槽            ← 这一层的渐变压掉了前面所有
```

后果很具体：在 `theme.css` 里改 `.btn.primary` 的颜色**不会生效**，
因为 `atmos.css` 第 225 行还在用 `#bb4d38 → cinnabar → #8f3325` 的渐变盖着它。
同一个 `.chipbtn` 在 `ui.css` 里还有两份（452 行与 1928 行，相距 1500 行），改一次要改两处，
而且前面那份里的 `#fdf4ea` 是死代码。

本轮收权（像素级等价，只搬不改值）：

| 文件 | 现在负责什么 | 不再负责什么 |
|---|---|---|
| `theme.css` | 令牌 + `.btn` 的结构（盒子、尺寸档、禁用态） | 按钮的颜色、材质、悬停 |
| `ui.css` | **唯一视觉权威**：五档操作、卡片三型、弹层与提示条 | — |
| `atmos.css` | 其它物件的厚度（槽位、卡面） | `.btn` 系列（整段删除） |
| `carved.css` | 刻痕皮肤的**变体**，必须 `body.carved` 前缀 | 全域覆盖 |

材质没丢，改为五个令牌（`theme.css :root`）：`--grad-solid` / `--grad-solid-hi` /
`--grad-solid-dn` / `--lip-solid` / `--sh-solid` / `--solid-edge` / `--grad-alert`。
以后换主按钮的颜色只改 `--cinnabar`，一条链自动跟着走。

## 四、刻痕皮肤（`body.carved`）与 WB-3 的三处冲突

`5dd2309` 把「刻在甲骨上」设为**默认**皮肤，这一层与 WB-3 的原则正面相撞，必须记一笔：

1. **27 个 `!important`**。用 `!important` 去压组件层，等于宣布"组件层从此不可改"——
   任何后续对 `.btn` 的修正都会静默失效。`body.carved` 前缀（0,2,0）本来就压得过
   `ui.css` 的（0,1,0），不需要这把大锤。我补的规则一条 `!important` 都没写，可作对照。
2. **49 处硬编码色值**，直接违反 TASK「业务 CSS 内 grep 不到硬编码色值」。
   已抽出五个皮肤内令牌供新规则复用（`--carve-face / --carve-line / --carve-inset /
   --carve-hi / --carve-text`），上面已有规则暂未回头改——那边可能同时在编辑。
3. **筛选片漏网**。图鉴页 7 个 `.chipbtn` 仍是近白色胶囊，压在骨底上像贴纸。
   已补（见 `carved.css` 末尾「WB-3 补丁」）：改成同一套凹槽 + 选中态淡朱砂。

另外一处需要方向拍板，我没有动：`carved.css` 把 `.toast` 从深墨块改回了浅骨气泡。
`direction.md` 的口径是「学会了是拓」——深墨块用于弹层/详情/结算；
提示条属于"页面之外的一层"，改浅之后它和卡片就分不清层次了。
