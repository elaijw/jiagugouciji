# tokens 落地指令（WB-2 执行单）

> 执行人：WorkBuddy 或 DSH 任一方都可。**只需三条命令，执行器已写好在 `dev/_land_tokens.py`。**
> 前置：`collab/01-design/tokens-20261022.css` 已定稿（102 个变量，全覆盖旧令牌）。

## 一句话

把 `theme.css` 的 `:root` 换成新色板，删掉两个 `html[data-theme="bone"]` 块（否则新色板不生效），升级缓存戳。**不改任何选择器、不改 js、不改玩法。**

---

## 一、先明白为什么不能"只删那两个块"

这两个块删掉之后，`field-notebook.css` 里那 39 个变量会**回落到 `theme.css` 的旧值**——那是另一套皮肤（`--bone:#f2e8d5` 发黄、`--r-xs:0` 全方角、`--sh-1:none` 无投影）。也就是说：

> **只删块 = 全站瞬间退回旧视觉。** 不是变干净了，是变回两个月前。

所以顺序必须是「先粘新 `:root`，再删旧块」。这个顺序下，中间态是「新变量被旧块盖住」＝画面不变，是安全的；反过来就会出现一屏发黄的中间态，容易被误判成"改坏了"。

## 二、还要明白为什么不能"只粘新 `:root`"

`js/core/build.js` 会给 `<html>` 写 `data-theme="bone"`，于是 `html[data-theme="bone"]`（权重 0,1,1）压过 `:root`（0,1,0）。**只要那个块还在，粘进去的新值一个都不会生效，而检查代码却看不出问题。** 这个坑之前在描边色上踩过一次。

## 三、119 处引用的兼容问题（已解决，但要知道）

旧代码里有一批变量**不在两个 `:root` 里，只出现在 `theme.css` 的主 `:root`**，但被大量引用：

| 变量 | 引用 | 处理 |
|---|---|---|
| `--gold` | 41 | `var(--bronze)` |
| `--line` | 38 | `var(--edge)` |
| `--sh-1` / `--sh-2` | 16 / 11 | 保留 `none`，任务 #2 逐个改 `--lift-1/2` |
| `--sh-3` | 4 | 保留原值 |
| `--bone1` / `--bone2` | 4 / 5 | 保留原值 |

这些**已经写进 tokens 的「兼容别名」段**。替换 `:root` 时如果手抄漏掉，这 119 处会直接失效（属性整条不生效，不报错，最难查）。用执行器替换就不会漏。

## 五、落地后画面会变的，只有这四处（其余应当逐像素不变）

绝大多数变量在两套里取值相同，所以落地后画面应该**几乎看不出变化**。如果变化明显，说明某处硬编码在起作用，而不是 tokens 生效了。

| # | 变量 | 变化 | 影响 |
|---|---|---|---|
| 1 | `--ink-2` | `#61746b` → `#5e7167` | 说明文字略深一档。这是为了把 4.40 提到 AA 4.60 |
| 2 | `--shadow` | `0 16px 44px` → 双层 `lift-3` | 卡片阴影更薄更散，不像一块灰 |
| 3 | `--sh-overlay` | `0 18px 44px -16px` → `lift-3` | 弹层阴影同上（4 处引用） |
| 4 | `--r-lg` | **`0` → `24px`** | ⚠ 原本用 `--r-lg` 的方角会变圆角。`field-notebook.css` 里只覆盖了 `--r-xs/sm/r`，漏了 `--r-lg`，所以它一直是 theme 的 `0`。如果某处设计意图就是方角（文物展示型卡片），改 tokens 里 `--r-lg: 0`，或在那一处写死 `border-radius:0` |

**新增变量无副作用**：`--veil`、`--solid`、`--solid-hi`、`--danger` 一族、`--lift-1/2/3`、`--speck` 一族、`--focus` —— 旧代码不引用它们，落地当刻不产生任何视觉变化，供任务 #2 使用。

## 六、一个容易误判的验证要点

tokens 落地后，`field-notebook.css` 里那 **221 处硬编码**会继续盖在变量之上。所以：

> **「画面没变化」不等于「tokens 没生效」。** 恰恰相反，它说明硬编码在主导。

要证明真的生效，读计算值而不是看颜色：

```js
getComputedStyle(document.documentElement).getPropertyValue('--ink-2').trim()
// 期望 '#5e7167'（落地前是 '#61746b'）
```

这条可以作为 04-verify 的一条独立检查项。硬编码清理归任务 #2，不在这条指令里。
