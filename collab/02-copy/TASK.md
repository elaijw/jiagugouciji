# 任务书 · GPT6luna（叙事与文案）

> 先读 `collab/README.md`。你只写 `collab/02-copy/` 下的 JSON 与 MD。
> 不要改 `css/`、`js/`、`index.html`。

## 背景

项目：《字趣·甲骨构字记》——以甲骨文为题的文化游戏，三关：
1. 甲骨构字（入门认知）
2. 殷商王邑（在插画上点实物认字）
3. 构件讨伐（把 Boss 字形拆构件 / 斩笔画）

角色「龟宝」是贯穿全程的向导。目标：让用户感觉「自己在发掘一段沉睡的文明」。

**重要**：你写的是**叙事与文案层**，不改世界观里的历史事实。
凡涉及字形、释读、年代的具体说法，必须来自站内已有材料或公开可靠来源，**不确定就不写**。

## 任务

### GL-1 三关叙事（`chapters.json`）
每关给四个字段（照 `collab/_templates/content.schema.json`）：
- `name`：章节名（4 字以内）
- `role`：用户在关卡中的身份（如「文明发现者」）
- `enter`：进入时的一句话（≤24 字，有画面感，不喊口号）
- `clear`：通关时的一句话（≤24 字，落在「你学会了什么」，不吹）

要求：三关连起来是一条成长线（发现 → 理解 → 掌握），不是三个并列难度。

### GL-2 龟宝台词（`guibao.json`）
三态各 8–10 句，覆盖：开场 / 答对 / 答错 / 卡住 / 通关。
- `curious`：好奇、会问问题，不装懂
- `partner`：会观察、给线索，偶尔吐槽
- `guardian`：沉稳、并肩作战，关键时刻提醒

要求：**答错时不责备、不贴标签**（不用「你不行」「太粗心」这类话）。

### GL-3 首页文案（`home.json`）
`title` / `subtitle` / `cta` / `progress_label` 四个字段。
- 标题 ≤10 字
- 副标题 ≤24 字
- 按钮 ≤6 字
禁止用「震撼」「颠覆」这类营销词。

### GL-4 视觉规范（`视觉规范.md`）
- 色：主/纸/铜/锈，各给十六进制与用途
- 字号阶梯：标题/正文/说明/角标四级
- 间距：4/8/12/16/24/32 六档
- 圆角：方角（文物）/圆角（对话）/胶囊（按钮）三种
- 图标：统一线宽，禁止混搭写实与卡通
- 明确写出「不要做什么」（例如：满屏卷轴、每个按钮都发光）

### GL-5 素材清单（`素材清单.md`）
表格：`用途 | 尺寸 | 来源 | 许可 | 是否已入库`。
- 只列**已在仓库里**的（`assets/` 现有 110 张，含 21 张 Boss 图）
- 需要新增的单独列「待授权」，**未授权的不许落盘**

### GL-6 验收话术（`验收话术.md`）
给每个模式写「该看到什么」：3–5 条，供 DSH 对照验收。
例：「进入第二关，能看到龟宝在左侧探头，点字卡后出现拓片。」

## 约束
1. 只写 JSON/MD；不动代码
2. 字段名严格照 schema，缺字段会被前端拒绝
3. 不编造历史事实与出处；引用必须可核
4. 文案要能直接上屏：不超过给定字数，不用 Markdown 标记（界面不渲染）

## 验收（DSH 跑）
- JSON 能被解析、字段齐全
- 三个 JSON 的字数都在限制内
- 文案里没有「未考证的断言」（人工抽查 10 条）
