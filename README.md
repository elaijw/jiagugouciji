# 字趣 · 甲骨构字记

一个以甲骨文为题材的**汉字文化互动游戏**。
第一关由龟宝带玩家边拼构件边学甲骨知识；第二关通过主题小地图逐步点亮王邑总图；第三关保留进阶 Boss 战。

> 本项目前身是单文件原型《字从契来》。现按平台化思路重构：
> **新玩法是一个模块文件，不改动平台其余部分。**

---

## 这是什么

| | |
|---|---|
| **形态** | 纯静态网页（H5）。无需服务器、无需构建、无需数据库 |
| **运行** | 双击 `index.html` 即可本地打开；上传到任意静态托管即可在线访问 |
| **数据** | 全部保存在本机浏览器（`localStorage`），**不上传任何服务器** |
| **依赖** | 零。没有框架、没有 CDN、没有外部字体与图片 |

**为什么不用 ES module**：`import` 在 `file://` 下会被浏览器的 CORS 策略拦住，
必须起服务器才能调试。这里改用传统 `<script>` + 全局命名空间 `App`，
**既能拆文件、又能双击打开、还能直接传 GitHub Pages。**

## 玩法一：甲骨构字 · 龟宝入门

一轮包含 5 次低压力练习，无倒计时。玩家从甲骨构件选项中拼出题面字；每题旁边都有一条简短的甲骨知识，拼对后由龟宝讲解字卡释义与构件组合。答错可调整后重试，也可求一个构件提示。

### 字形呈现：构件与字卡都是真甲骨字形

这一条曾经是坏的：`pieceForm: 'ob'` 默认就开着，代码也设了 `data-ob` 属性，
但 **CSS 里从来没有对应的规则**——`.g.ob` 只写了
`font-family: "Courier New"`，也就是**把同一个今字换个等宽字体**，
设置项却写着"甲骨文"。等于骗人。

现在改为渲染**内联 SVG 真字形**（取自 `glyph-parts.json`，CC BY 4.0）：

| 位置 | 显示 |
|---|---|
| 题面 | **今字**，作为辨认入口 |
| 构件选项 | 来自字形数据的真甲骨构件，点选组成答案 |
| 拼对之后 | 显示项目字卡释义、构件组合示意与龟宝知识讲解 |
| 全程 | 不显示虚构的整字甲骨形；组合示意不冒充原甲骨刻形 |

### 为什么字卡出今字、而不是甲骨形

题面是**今字**，构件选项是真甲骨字形。拼对后只展示数据里收录的构件组合：

```
今字题面  →  点选真甲骨构件  →  龟宝讲解释义、构件与甲骨知识
```

知识卡会依次介绍甲骨材料、占卜记录、常见记事主题，以及如何观察字形。相关事实以博物馆与 UNESCO 的甲骨文资料为基础。

### 合体字怎么"组成"甲骨文

37 个构件全部有真字形；34 张字卡是**合体字**，而数据集里只有单构件，
没有整字。所以字卡是**用它的构件拼出来的**：

- 多数甲骨合体字为左右并置（如 牧 = 牛＋又、饮 = 人＋酉）
- 屋盖类与"手在树上"类为上下相叠（家 安 灾 牢 采 集 共 兵 焚）

> 这只是**组合示意**，不代表该字甲骨原形的精确位置——界面上一律标明
> 「组合示意」，不冒充原形。这是刻意的克制：字形一律用真货，
> 宁可标"示意"，也不画一个看起来像、其实错的甲骨文。

## 玩法二：殷商王邑（主题小地图 · 王邑总图）

**第二关是整条主线。** 玩家逐枚完成当前小地图中的甲骨字形学习；学完一幅后，王邑总图点亮对应区域并解锁下一幅。
目前五个主题先沿用已有的字形分区作可替换框架，等待用户后续提供正式主题与教学内容。

### 旧版单图交互说明

以下灰度地图、遮罩与热区坐标记录的是旧版单图玩法实现，不是当前玩家流程。当前主图是 `assets/wangyi-atlas.svg`，由项目原创绘制，是学习用的聚落意象示意，并非考古复原。

```
地图（灰）                          点实物
┌────────────────────────┐        ┌──────────────────────────┐
│  山川、河流、城邑、牲畜    │        │ 甲骨文原字                │  ← 上：原字
│  整幅灰度化              │  ───▶  │   [完整甲骨字形] + 释义    │
│  认出的字 → 那块透出彩色   │        │  组装区（原字淡淡作底）    │  ← 中：拼
│                        │        │  [笔画][笔画][笔画]…       │
└────────────────────────┘        │ 笔画（拖到上面）           │  ← 下：部件
   进度 7 / 61 个实物已点亮         │  [笔][笔][笔][笔]…        │
                                 └──────────────────────────┘
```

### 点亮是怎么做的

不用切图、不用预做遮罩。**同一张图放两层**：

- 底层：原图，CSS `grayscale(1) brightness(.72)`
- 上层：同一张原图，用 `<mask>` 只露出「已拼成」的那些字的圆形区域

拼成一个字 = 往 mask 里加一个白色圆 → 那块就变彩色。
圆心/半径直接取热区的 `x,y,r`，所以**「亮的地方」就是「点的地方」**；
圆的填充用径向渐变，边缘是柔和光晕，像一盏盏灯亮起来。

### 笔画拆分（拖拽构字的依据）

`glyph-parts.json` 里每个字按 `M` 起点拆成独立笔画：

- 61 个字共 **362 笔**；山 1 笔，鼎 11 笔，鱼 16 笔
- 数据集 61/61 全部只用绝对 `M/L` 命令，所以按 `M` 切是安全的——每段就是一笔
- 每笔带**画布坐标**包围盒 `c`：部件池里按自身包围盒单独显示，
  拖回目标时用同一套画布坐标就位——所以是「拼回原字」，不是随便贴
- 判定用「落点与本笔应在位置的圆心距」，**必须摆对地方**才算，不是拖进去就行

> 山只有 1 笔，拆不出部件，这个字的构字没有挑战——自检会把它列出来。

### 数据

全部在 `js/core/levels.json` 的 `map.zones[].objects`：

```json
{ "id": "land", "name": "山川", "note": "山水川泉谷丘土石田",
  "objects": [
    { "char": "山", "x": 900, "y": 72, "r": 76, "meaning": "三峰并立" }
  ] }
```

- `x,y` 热区圆心 / `r` 半径（同时决定点亮区域大小）/ `meaning` 象形说明
- 坐标在 **1800×907 的底图像素空间**里手工读图定位，与 `viewBox` 一一对应
- 改完跑 `python dev/_build_object_map.py`（带自检）+ `python dev/_build_leveldata.py`

### 加实物时的自检

| 检查 | 为什么 |
|---|---|
| 缺字形 | 引用了没有甲骨字形的字，构字页会是空的 |
| 重复摆放 | 同一个字摆两次，会让人以为能点出不同东西 |
| 热区重叠 | 圆心距 < 半径和的 0.75 就报——两个热区叠一起会点不准 |
| 越出画布 | 圆心跑出 `viewBox`，点了没反应 |
| 底图缺失 | 图片路径写错会开天窗（**直接中断生成**） |

### 当前交互地图（2026-10-12）

第二关以「主题小地图学习 → 完成后点亮王邑总图对应区域 → 解锁下一幅」为主线。
当前五个主题沿用旧数据分区作占位；用户之后提供正式主题后，再替换分区名称与讲解内容。
`assets/wangyi-atlas.svg` 是项目原创绘制的学习用聚落意象示意，并非考古复原图。

### 换底图

`dev/_swap_map.py`：把生成的底图缩到 1800 宽（16:9 不裁切）→
存为 `assets/wangyi-map.jpg`，并输出**带 100px 刻度的预览**用来读图定位。

换图后 `viewBox` 要跟着改（脚本里的 `VW/VH`），**所有热区坐标也得重标**——
坐标是绑在底图像素上的。

### 底图出处

仓库保留的旧底图 `assets/wangyi-map.jpg` 由 **Agnes AI**（`agnes-image-2.1-flash`）生成，
无第三方水印，出处仍记录在旧版 `map.bgCredit`。当前交互版使用上方提到的原创 SVG 总图。

> 只把它当**画**用。字形一律用项目里那套真货（Li & Bian 数据集，CC BY 4.0）——
> AI 画的「甲骨文」一定似是而非，**拿它当字形就是污染数据**。

### 曾经走错的方向（留个记录）

以下判断记录的是旧版需求与试错过程。2026-10-12 用户明确要求第二关采用主题小地图教学、顺序解锁并逐域点亮大地图；当前功能按这一新要求实现，旧判断不再限制第二关。

这一节错了三回，都记在这：

1. **做成「区块闯关」**：区块 → 关卡 → 答题，还有解锁闸门与拼图块点亮。
   方向错了——需求是「看图认字」，地图即教材。
2. **把 61 个字形标记摆在画上**：盖住画，也遮掉了甲骨文「象形」这个看点。
   改成画保持干净、热区隐形。
3. **字卡直接显示拼好的甲骨形**：那等于把答案给了。
   改成「给构件、让玩家自己组、拼成才揭晓」。

## 玩法三：构件讨伐（BOSS 战）

**拆字为武，组构为招，繁笔破防。**

### 界面：骨片选关 + 横版对战

- **选关**：21 关沿一枚**甲骨片的轮廓围成一圈**，一关一关推进，
  **通关才解锁下一关**。轮廓是 18 个顶点、刻意做得不规整（带缺口），
  底板上叠了极淡的卜辞竖行；节点是串在骨片边上的**圆珠**，
  已通关那段路径描绿，骨片正中是真实进度。

- **作战**：**横版**三段式战场——
  **左侧预留「项目形象」位**（虚线框，后续把角色立绘放进去即可），
  中景是远景装饰，**右侧是 BOSS 形象**；上有 HUD（关卡 / 阶段 / 血量），
  下有提示、战报与操作。

### 打法：阶段一自己从构件池挑构件

**一阶合体字**（涉 鸣 焚 逐 安 家）：阶段一从**构件池**里自己挑构件砸上去。

- 池子里是**全部 37 个构件**，只有 2 个左右是对的，其余 28 个是干扰项。
  只给正确项等于报答案，所以必须给全。
- 挑错记一次**误选**、进战报，**不扣血**——但意味着还没看清它的构件。
- 零误选通关记为**完美通关**，骨片上的珠子会描金。
- 这一阶段**不能直接点 BOSS 身上那块**（点了等于把答案指出来），
  身上那块只作展示；战场会带 `.bd-field.pool-only`。

**二阶独体字 / 终极繁复字**：身上没有可拆的构件，**直接点 BOSS 拆笔画**。
构件池不出现在这两档。

之所以这么分：越早、越图画化的字形越没有清晰的部件边界（車 17 段、虎 17 段），
硬按构件拆就是拆不动。**一阶拆构件、终极斩笔画不是两套玩法，是同一件事的两端。**

### 一条规则：甲骨形上不印现代字

默认**只见甲骨形**，鼠标悬停 / 键盘聚焦 / 按住（触屏）时，现代字才**浅浅浮出**，
压在字形中央。选关节点与作战界面的 BOSS 名都是如此（BOSS 名先显示「？」）。
已通关的关卡与通关结算页例外——那时已经揭晓过，常显。

开战战报与副标题也一并**不剧透**：只说「一尊 N 段的古字挡在面前」，
不报字名，也不报构件（写"水＋止"等于报答案）。

### 三档 BOSS

| 档 | 代表 | 身体 | 打法 |
|---|---|---|---|
| **一阶 · 合体字** | 涉 鸣 焚 逐 安 家 | 由构件拼成（涉＝水＋止，共 10 段） | **拆构件**。构件决定它的能力：拆「止」封走位、拆「口」封印技能、拆「水」「火」消属性 |
| **二阶 · 独体字** | 山 人 木 日 月 水 | 独体象形，1~5 段 | 直接拆笔画，几笔就散 |
| **终极 · 繁复字** | 象 龍 鳥 鼓 馬 龜 舞 車 虎 | 图画型古字，**6~17 段连续纹路** | 硬拆构件无效，只能**斩笔画** |

> 一阶的合体字，数据集里没有完整甲骨形——身体直接用「甲骨构字」那套
> **构件现场组合**拼出来。所以拆掉一个构件，身体当场就缺一块，视觉反馈天然成立。

### 战斗三阶段

```
阶段 1 构件压制   拆掉它的构件／笔画 —— 掉血，并报出这个构件管什么用
                  例：「消水属性（水）水——它的水脉。断开之后，水属性攻击当场失效。」
阶段 2 构件崩坏   它把拆散的部件又吸回去，形体错乱、构件混同
                  （复刻真实甲骨文的异体乱象）—— 此阶段【构件攻击失效】，点它只掉提示
阶段 3 笔画终局   它化为无构件的纯笔画体，一段一段斩断，斩完即杀
```

### 为什么终极 BOSS 要换打法

「車」17 段、「虎」17 段、「舞」16 段——这类字**构件重叠、混同，没有固定部件**，
硬按构件拆是拆不动的。设计上正好对应一个真实的古文字现象：
越早、越图画化的字形，越没有清晰的部件边界；等到能清楚拆成构件时，
它已经离「画」很远了。**所以一阶拆构件、终极斩笔画，不是两套玩法，
是同一件事的两端。**

### 加 BOSS 时的注意

- BOSS 字形由 `dev/_gen_glyph_parts.py` 的 `BOSS` 表收录（只做字形，
  不进地图、也不进「甲骨构字」的构件台）
- 段数决定它适合哪一档：**1~5 段**放二阶，**6 段以上**放终极
- 改完跑 `python dev/_build_boss.py`（写内容）+ `python dev/_build_leveldata.py`（内联）
- 验证：`python dev/_run_bo.py`


`data-nav` 固定为 `top`，宽屏玩法（`layout:'wide'`）的选择器
不再依赖 `data-nav="side"`，直接挂 `.app-shell.layout-wide`。

### 汉字图鉴的数据来自哪里

`js/core/atlas.js` 把关内**已有的四类真实内容**汇成一张表（不放任何编造内容）：

| 档 | 数量 | 来源 | 带什么 |
|---|---|---|---|
| 构件 | 37 | `data.js` 的 `BUILTIN_PIECES` | 分类（自然/人体/动植物/器物） |
| 合体字 | 34 | `data.js` 的 `BUILTIN_POOL` | 构件、释义、卜辞出处、等级 |
| 王邑实物 | 61 | `levels.json` 的 `map.zones[].objects` | 分区、释义 |
| 讨伐字形 | 21 | `levels.json` 的 `boss.tiers[].list` | 档位、构件、段数 |

同一个字可能出现在多处（「山」既是构件、又是实物、又是 BOSS），
各档分别计数；**总进度按去重后的字算**（当前 102 个去重字 / 153 条）。

"已解锁"是并三个玩法各自的进度（王邑的点亮记录 + 讨伐的通关记录）。
甲骨构字目前不落盘进度，所以不参与统计——**不虚报**。

**合体字在数据集里没有整字甲骨形**（这是真实情况）。图鉴对它们显示
**构件组合示意**：按「甲骨构字」同一套把构件并排拼出来，卡片上标「组合」、
格子加虚线内框，与整字真字形区分开，不冒充整字。

## 界面与样式

样式分四层，加载顺序即覆盖顺序（`app.css` 最旧，`modes.css` 最专）：

| 文件 | 职责 | 改动原则 |
|---|---|---|
| `css/app.css` | 旧单文件版遗留（构件格、比分板、棋盘、媒体查询） | 只做令牌对齐，结构不动 |
| `css/theme.css` | **设计令牌 + 通用组件 + 弹窗/抽屉 + 状态提示** | 改样式优先改这里 |
| `css/ui.css` | 壳层布局：侧栏、内容列、页头页脚、首页卡、模式卡 | 布局问题改这里 |
| `css/modes.css` | 三个玩法各自的界面 | 玩法专属样式 |

### 设计令牌（`theme.css` 顶部）

颜色、间距、圆角、阴影、动效、层级、字号**全部走令牌**，不要写魔法数字。

```css
--s-1…--s-10     间距刻度（4 的倍数；--s-9/--s-10 是分区节奏用的大档）
--r-xs…--r-lg    圆角（矩形一律 0；--r-pill 只留给点位/进度条这类本来就是圆的东西）
--sh-1/--sh-2    极轻的一档（0 1px 0，只到"分得开"为止）
--sh-3           浮层与悬停抬起（模态/轻提示/下拉/卡片 hover）
--lh-body/prose/head/flat   行高（正文 1.9 / 长段 2.0 / 标题 1.4 / 盒内文字 1.0）
--rule/--rule-in/--rule-soft 罫线（1px，层次主要靠它）
--crack/--crack-size         兆：灼烧裂纹（甲骨独有的分区线，抽象叉线不是字；见下）
--ground/--sheet/--sheet-in/--sheet-in2  面料分层
--fiber/--fiber-op           纸纹（浅色面），assets/paper.png
--bone-tex/--bone-tex-size   骨材质（页底），assets/bone.png
--patina/--patina-2/--pit    骨上的褐斑与虫蛀孔
--ink-carve/--rub/--rub-2    刻辞的墨 / 拓黑与拓片亮处
--glyph-line/--glyph-rub     字形描边色：浅底用前者，拓片反白用后者
--t-fast/base/slow + --ease   动效时长与缓动
--z-nav/top/toast             层级
```

> `theme.css` 里令牌有**两处**定义：`:root` 与 `html[data-theme="bone"]`。
> 后者权重更高，**改颜色必须两处都改**，否则页面上毫无变化（踩过）。

#### 这一层是照文化/博物馆类网站的做法定的

参考两份**实测出来的真美术馆设计系统**，以及一篇文化内容页专文：
[大阪中之岛美术馆](https://kzhrknt.github.io/awesome-design-md-jp/design-md/nakanoshima-museum/DESIGN.md)、
[森美术馆](https://kzhrknt.github.io/awesome-design-md-jp/design-md/mori-art-museum/preview.html)、
[文化内容页的留白、字体、配色与滚动节奏](https://htmlpage.cn/topics/design/atmosphere-web-design-for-cultural-content)。
几条结论落到了本项目的令牌里：

| 结论 | 落地 |
|---|---|
| **层次主要靠 1px 罫线与面色浓淡**，阴影只到"分得开"为止 | `--sh-1/--sh-2` 是极轻的 `0 1px 0`；`--sh-3` 只给浮层与 hover 抬起 |
| 正文行高要舒展（两馆分别是 **2.0 / 1.75**） | `--lh-body: 1.9`（中文笔画密，取中间偏松） |
| **矩形圆角为 0**（中之岛全站唯一的圆是开馆日历的日期格） | `--r-xs…--r-lg` 全为 0 |
| 字距只给标题与极小号字，**正文 normal** | 标题 0.06–0.2em；正文不加字距 |
| 强调色**点状使用**，不铺面 | 朱砂只留主 CTA、当前态、印章、状态；编号等改青铜 |
| 动效要"安静"（美术馆级在 300–500ms） | `--t-base: .26s`、`--t-slow: .42s`，缓动换成起步稳的那条 |

**后来偏离了这一层，是故意的。** 严格照上面做出来的结果是"素、空白多"——
低饱和 + 无阴影 + 圆角归零 + 装饰全退，读起来干净，但像一张平的白纸。
所以又补了**材质**这一层：骨面斑驳、纵向骨纹、虫蛀孔、真字形刻辞、兆裂分区线、
图鉴的墨拓。（这就是为什么 `--sh-1/--sh-2` 现在不是 `none`。
"干净"与"有物质感"要同时要，靠的是**把质感做在材质上，而不是加装饰花纹**。）

中文排版另外做了两件：`line-break: strict`（禁则走严格模式，
否则 `「」、。` 会掉到行首）与段落 `text-align: justify`（中文等宽，
两端对齐不会像西文那样把字间拉出空洞）。段落两端对齐**只给段落**，
按钮与导航这类短标签被拉伸会很难看。

**改配色前先跑 `node dev/_contrast.js`。** 它会把每一组"文字色 × 底色"算出来，
低于 AA 4.5:1 的会单列。当前基线是 **1 处**：

- `--edge on --bone` —— 描边/分隔线，本就不是文字

> 甲骨字形原先用 `--bronze(#8c8066)`，在骨白底上只有 **3.20**，线条发虚。
> 现已改用专门的 `--glyph-line(#524834)`（骨白 **7.40** / 最深的 bone-lo 上 6.60），
> 同时给字形 path 加 `vector-effect: non-scaling-stroke`，线宽改用绝对像素——
> 原来的线宽按画布 0.9 单位随渲染尺寸缩放，渲染到构件台的 24px 时只有 0.31px，
> 被抗锯齿成一根浅灰影。详见 `css/modes.css` 里「甲骨字形的线宽」一节。

> 注意有两套同色系的值不能混用：`--cinnabar/--bronze/--green/--blue` 是**底色**
> （按钮、印章、徽记），`--cinnabar-tint/...` 是**文字色**（更深）。
> 把文字色拿去当底色，白字压上去会立刻不可读。

### 组件规范

- **按钮**：`.btn` 为次按钮；`.btn.primary` 主操作；`.btn.danger` 危险操作；
  `.btn.ghost` 弱化操作。尺寸 `.sm` / 默认 / `.lg` 三档，高度 28/34/40。
  四态齐全：hover 变色 → active 下沉 1px → `:focus-visible` 焦点环 → disabled 半透明。
- **面（卡片/面板）**：`.sect .panel .console .home-card .mode-card .tl-table` 共用一套
  圆角/描边/阴影。可点的面在 `.scene` 下悬停会轻微抬升。
- **表格**：表头用低饱和青铜底，行悬停高亮，末行不收口线。
- **表单**：输入框/下拉/文本域/复选/单选/滑块统一样式，聚焦时朱砂描边 + 柔光环。
- **弹窗/抽屉**：`.overlay`（遮罩）+ `.edbox`/`.imgbox`（主体）+ `.edhead`（标题栏）
  + `.edbody`（内容）+ `.edfoot`（底部操作）。**桌面居中弹出，窄屏自动变全屏抽屉。**
- **状态提示**：加载/空/错误三态。
  其中错误态**不需要改 JS**：平台把「找不到玩法 / 玩法未实现 / 玩法加载出错 / 数据缺失」
  都渲染成所在容器里唯一一段 `.lead`，样式用 `.scene > .lead:only-child` 与
  `.mode-host > .lead:only-child` 精确命中（正常导语有兄弟节点，不受影响）。

### 成就与评级（`js/core/achievements.js`）

把三个玩法的进度汇成一条成长线，显示在首页「内容探索」里。

- **评级**：由**收集度**换算的称号，沿用甲骨学里的身份——
  `未入门 → 初识契文 → 能读骨片 → 通晓卜辞 → 贞人门下 → 与甲骨共语`。
  卡片上还会写"再收 N 个字可升下一级"。
- **成就 14 项**：收集里程碑、王邑点亮、讨伐通关/完美通关、构字答对数、三艺俱全。
  **未达成的不灰掉了事**——给进度条与 `now / need`，让人知道还差多少。
- **新达成会弹提示**：玩法里**不埋钩子**（那要把三个模块都改一遍），

  首次运行会把当前已达成的直接记为已知，不会一开站就弹一排。

全部数值都从真实进度算，**没有写死的假进度**。

### 几条踩过的坑

- **别给容器加 `transform`**。`.scene` 的入场动画只做淡入不做位移——
  一旦有 `transform`，它就成了 `position:fixed` 后代的包含块，
  动画那 180ms 里固定定位元素会跑位。
- **`prefers-reduced-motion` 里只停动画，不要顺手改样式**。
  早先为了"减弱动效"给首页标题去掉 `background-image`，
  而文字是透明的、靠背景裁切显色，结果标题直接消失。
- **`className.indexOf('on')` 会命中 `done`**。判断选中态要按整词匹配
  （前后补空格），这个坑在测试驱动里踩过一次。

## 玩法模块的约定

新增玩法**只需新建一个文件**，放在 `js/modes/` 下，并在 `index.html` 里加一行 `<script>`。

```js
App.modes.register({
  id: 'your-mode',
  name: '玩法名',
  tagline: '一句话说明',
  desc: '展开说明',
  icon: '单',                 // 单字图标
  accent: 'var(--cinnabar)',  // 图标底色
  tags: ['单人', '计时'],
  minPlayers: 1, maxPlayers: 2,
  status: 'ready',            // ready（可玩）| wip（开发中）| planning（筹备中）
  layout: 'wide',             // ''（默认，内容列限宽 860/900px）| 'wide'（占满整个界面）

  data: {                     // 需要哪些数据，平台会准备好
    packs: [{ type: 'cards', role: 'main', label: '字包' }],
    assets: []
  },

  settings: [],               // 可选设置项声明（也可以自己在 mount 里画）

  // 平台给你一个空容器 host，以及一份上下文 ctx
  mount: function (host, ctx) {
    // ctx.primaryPack  已解析好的主数据包
    // ctx.packs        该模式可用的全部包
    // ctx.ui           共享渲染工具（el / esc / toast / signed …）
    // ctx.store        命名空间化存储
    // ctx.theme        读写主题
    // ctx.nav          跳转（home / modes / replay）
  },

  unmount: function (host) { /* 清定时器、移除 body 上的临时类 */ }
});
```

**平台保证**：
- 模式之间互不干扰（各自 `mount`/`unmount`，不共享全局状态）
- 离开对局时自动调用 `unmount`
- 内容包按模式声明的类型自动解析，模式不必了解存储细节
- `layout:'wide'` 时：侧栏让位（`display:none`）、内容列改单列并放开限宽，
  整块内容占满界面。下一次 `render` 会自动清掉这个类，模式不必自己收拾

> **实现提示（踩过的坑）**：宽屏要放开的不止 `.app-main`（`max-width:900px`），
> **还有 `.wrap`（`max-width:860px`）——`#sceneRoot` 本身就是 `<main class="wrap">`**。
> 只放开前者的话地图仍然只有 832px 宽；逐层量祖先的宽度才找得出来。
> 另外 `App.modes.register()` **只复制它列出的字段**，新增描述字段（如 `layout`）
> 必须同时加进 `modes.js` 的白名单，否则 `scenePlay` 里读到的是 `undefined`，
> 规则静默失效。

## 内容包（数据层，界面已撤）

平台不只服务「字包」。`js/core/packs.js` 里登记了四类结构，新类型加一条 schema 即可：

| 类型 | 结构 | 用途 | 现状 |
|---|---|---|---|
| `cards` | `{ pieces:[], cards:[] }` | 字包（构件 + 字卡） | **内置 1 个**，甲骨构字在用 |
| `quiz` | `{ questions:[] }` | 题库 | 只有类型定义，无内容 |
| `atlas` | `{ entries:[] }` | 图鉴 | 只有类型定义，无内容 |
| `script` | `{ chapters:[] }` | 剧本 / 章节 | 只有类型定义，无内容 |

### 为什么把界面撤了

原先首页有一张「内容包」卡、设置页有一块「内容包」表。撤掉的理由：

- 那张表**只有一行**（内置字包），用户既改不了也加不了
- 说明里写「后续玩法引入新类型时会在此出现」是将来时的话，
  而 quiz/atlas/script 三类**只有类型定义、零内容、也没有添加入口**
- 首页卡片显示「字包 1 · 题库 0 · 图鉴 0 · 章节 0」——三个 0 看着像没做完
- 更关键：`packs.js` 其实有完整的增删改（`create/update/remove/setActive`），
  但**界面一个都没暴露**，等于摆了个用户动不了的架子

**数据层保留**（甲骨构字靠 `ctx.primaryPack` 拿字卡）；**导出/导入保留**，
并入设置页的「数据备份」——它是唯一的备份途径。
以后真要做内容编辑，再把界面加回来，底层能力都还在。

| **骨白** `#f2e8d5` | 页底、载体、亮面 |
| **朱砂** `#a63e2f` | 点睛、强调、主按钮（取自甲骨卜辞的"填朱"） |
| **青铜** `#8c8066` | 少量点缀、描边 |
| **拓黑** `#17120c` | 墨拓的底（图鉴拓片） |
| **骨斑** `#b9a480` | 骨上的褐斑、骨纹阴影 |
| 骨片轮廓（不规则八边） | 编号牌、放置槽、构件格、`.sheet` 骨版残边 |
| **兆纹**（灼烧裂纹） | 分区线（`--crack`） |

**只有一套外观：骨白**（`css/theme.css` 里以 `html[data-theme="bone"]` 组织）。
`data-theme` 由 `js/core/build.js` 写死，用户看不到也改不了——
站点是教育用途，不做外观开关，省得两套面色互相污染。
（曾经设想过"灼骨/骨白/素色"三套，已废弃；README 此处原先还写着三套，是过时描述。）

### 材质是怎么来的

"骨"不是一种颜色，是一件**物件**。所以页底不是一块平色，而是三层叠出来的：

| 层 | 内容 | 生成方式 |
|---|---|---|
| 1 | 竖向明暗渐变 | CSS（骨面本就不匀） |
| 2 | **骨材质**：斑驳 + 纵向骨纹 + 虫蛀孔 | `dev/_gen_bone.py` → `assets/bone.png`（512 无缝平铺，以 multiply 压在底色上） |
| 3 | **真字形刻辞**底纹 | `js/core/build.js` 的 `buildPatternURI()`，用 `App.glyphs.parts` 里的真字形实时合成 |

图鉴则整页做成**拓片集**：甲骨本来就是靠墨拓出版的，纸覆在骨上扑墨，
凹处（刻辞）留白，所以字形是**反白**的。墨底 + 字形反白 + 右下朱笔写今字。

### 首页骨片照

并且**整幅铺满首屏**（`object-fit: cover`），文字压在上面。

| 项 | 内容 |
|---|---|
| 文件 | [Ancient Chinese Writing on Ox Bone, Shang Dynasty.jpg](https://commons.wikimedia.org/wiki/File:Ancient_Chinese_Writing_on_Ox_Bone,_Shang_Dynasty.jpg) |
| 内容 | 商代刻辞牛骨，字口清晰可辨 |
| 摄影 | Gary Todd |
| 授权 | **CC0 1.0 公有领域奉献**（法律上无需署名，仍照标出处） |
| 原图 | 5184×3456 |
| 本项目所做 | 仅缩放与压缩（2400×1600，q78，332KB）；**未裁切主体、未做任何"修复"** |

选它的一个实际原因：**原片本身就是暗底**（骨片居中、四周深色展柜背景），
铺满整屏后文字压上去不必把照片压黑——压黑了照片就白铺了。

> 前一版用的是上海博物馆那张 800×800（CC BY-SA 3.0），
> 铺满 1440 宽要放大近 2 倍会糊，且底子是白墙，压暗后照片基本看不见，故替换。

> 选材原则：**不用来路不明的仿造字形**。数据集里没有的字（例如合体字的整字甲骨形）
> 就如实说明，改用构件组合示意并标注「组合」，不画一个假的冒充真字形。

### 声音：`assets/bgm-guzheng.mp3` + `assets/bone-clack.wav`

两段都是 Freesound 上的 **CC0** 素材（出处已核对到声音页本身的
creativecommons.org 链接，不是靠搜索条件推断）。

| 用途 | 文件 | 出处 | 授权 | 处理 |
|---|---|---|---|---|
| 背景音乐 | `bgm-guzheng.mp3`（85s，1.9MB，约 190kbps） | Freesound `472707`「guzheng solo」 | CC0 1.0 | 未改，整段循环 |
| 骨板拨动 | `bone-clack.wav`（0.22s，21KB，48kHz 16bit 单声道） | Freesound `702293`「Bones Clacking Against Floor」 | CC0 1.0 | 从 14.5s 原录音里切出**单次击打**，归一化到 -1.5dBFS，尾部 55ms 淡出 |

**为什么只能走 `<audio>`、不能进 Web Audio**：站是 `file://` 双击可跑的，
实测 `createMediaElementSource` 在 `file://` 下输出恒为 0（opaque origin →
媒体被判跨源、tainted → 静音）。所以音量只能用 `el.volume`，
也没有办法做滤波/压缩。相关验证脚本：`dev/_probe_filemedia.js`。

**降级**：两个文件任一加载失败就退回振荡器实时合成（`js/core/audio.js` 里的
`startSynthMusic` / `synthPluck`），不会整站无声。

**换素材**：把新文件放 `assets/`，改 `js/core/audio.js` 顶部的
`BGM_SRC` / `SFX_SRC`（记得同时改 `?v=` 后面的版本号）。
`dev/_cut_clack.js` 可以从任意一段敲击录音里切出干净的一击。

### 构件字形：`js/core/glyph-parts.json`

**61 个甲骨字形**，供拼字/拆字/配对三个玩法使用，同样出自上面这份数据集，
**CC BY 4.0，须署同一作者**。

- 内容：字 → `{glyphId, svg, bbox, sourceChar, unicode}`，SVG 内联（避免额外请求与 file:// 跨域）
- 画布：统一归一化到 100×100，按每个字形的实际路径坐标等比缩放并居中
- 署名与来源写在 JSON 的 `attribution` 字段里，随数据一起带走
- **重新生成**：`python dev/_gen_glyph_parts.py <上游稀疏检出目录>`
  上游仓库：`github.com/aylqs2025/oracle-bone-jgw-1203`（commit `5496ad5`）
- **不做分区索引**：早先曾按区块给字分组（landscape/creature/life），
  但那是按「单构件字」的思路建的；关卡改为「单字拆字」后，同一个字
  （如 日、月）既属于自然风光又是拆字构件，分组与实际内容脱节，
  还让拆字干扰项抽不到同域字。现只保留一张统一字表，
  哪些字用于哪一关由 `levels.json` 决定（内容与代码分离）。

已核对的两个坑：

| 构件 | 情况 |
|---|---|
| 门 / 贝 | 数据集以**繁体「門」「貝」**收录（glyphId 849 / 481），需按繁体查 |
| 囗 | 数据集**未收录**，但**不参与任何字卡**；借用「口」的方框形，JSON 内标 `isFallback` |

> 特别提醒：**不要手工编辑 `glyph-parts.json`**（文件首行已注明）。
> 它由脚本生成，手改会在下次重新生成时被覆盖。

## 开发自查

`dev/` 与根目录的 `_check*.py`、`_shots.py` 等脚本用于**在真实浏览器里验证**：

| 脚本 | 作用 |
|---|---|
| `_run_drive.py` + `drive.js` | 原有玩法（甲骨构字）：在 headless Edge 里走一遍全流程，回报状态与控制台错误 |
| `_run_wy.py` + `wy-drive.js` | 王邑闯关：验证解锁链、拆字与配对机制、未开放区块拦截 |
| `_gen_glyph_parts.py` | 由上游数据集生成 `glyph-parts.json`（含归一化） |
| `_build_leveldata.py` | 把两个 JSON 内联成 `_data.js`（file:// 下不能 fetch） |
| `_build_glyphcheck.py` | 生成字形对照页，含越界/过小检查 |
| `_syntax_probe.js` / `_verify_deploy.js` | 语法与部署资源大小写校验 |
| `_contrast.js` | 各主题配色对比度审计（WCAG） |
| `_cleanup_edge.py` | 安全清理无头 Edge（默认演练，`--kill` 才真关） |

> 这些脚本依赖本机的 Microsoft Edge 与 bundled Python，**不属于部署内容**，
> 上传时可整个排除。
>
> **驱动脚本请先过 `node --check` 再用**：括号失衡时 Node 会把错误报在**下一行**，
> 极易误判（本项目在此栽过跟头，排查被带偏很久）。`_run_wy.py` 已内置这道自检。
>
> **浏览器隔离**：所有脚本都用项目自己的 `_check/*profile`，
> **绝不按「进程名 + 启动时间」批量杀 Edge**——曾因此把用户正在用的浏览器
> 一起强杀了。要清理请用 `_cleanup_edge.py`（它按命令行里的
> `--user-data-dir` 精确识别，且有演练模式）。headless 跑完通常自行退出，
> 多数情况压根不需要清理。

## 已知限制

- **字体**：正文用系统宋体系列（Songti SC / Noto Serif SC / SimSun）。
  若目标设备缺字体会退化到默认衬线，观感略有差异。
- **浏览器能力**：标题的墨色渐变用 `background-clip: text`，
  已提供 `@supports` 降级；不支持时退回纯墨色。
- **存储上限**：`localStorage` 约 5MB。图片素材多时请及时导出备份。
- **未做后端**：无账号、无云同步、无排行榜。跨设备需手动导出／导入。
