## 2. 整体结构（务必先读这段）

站点现在**只有一条主线：数字博物馆是外壳**，玩法都在馆内开，不再跳 `#/play/*` 独立页面。

```
index.html
  js/core/*                     壳层、路由、数据、进度
  js/museum/museum.js           馆的 UI 层：路由/面板/拾取分发/导览/典藏/降级
  js/museum/museum3d.js         馆的 3D 层：大厅 + 各展区屋子（一个大 scene，切 visible）
  js/museum/museum-tex.js       字形/骨面画到 canvas 的工具
  js/museum/museum-audio.js     馆内环境音 + 单音效（顶栏「声音」开关）
  js/museum/glb.js              GLB 加载
  js/world/stage3d.js           玩法共用的 3D 舞台（渲染器/拾取/相机 tween）
  js/world/bone-float.js        第二关：骨片浮空（第一人称环视）
  js/world/boss3d.js            第三关：守字之骨（三阶段）
  js/world/battle-music.js      战斗音乐（纯 WebAudio 程序化）
  js/world/battle-sfx.js        战斗音效（纯 WebAudio 程序化，12 个事件音）
  js/modes/bone-build.js        第一关：甲骨构字（2D 入门课）
  js/core/progress.js           三关进度（build/float/boss），典藏区读它
```

### 路由

- `#/museum`、`#/museum/<zone>`：zone ∈ `gallery`（甲骨文知识厅）、`build`、`excavate`、`boss`、`collection`
  - 「文明序厅」已并入 `gallery`，`#/museum/prologue` 会落到 gallery
- `#/play/<modeId>`：还能用，但 `shell.js` 会渲染博物馆再 `App.museum.openPlay(id)`，地址栏改成 `#/museum`
- `#/atlas`、`#/archive` 等仍然存在（站点信息页，非博物馆主线）

### 馆内开玩法（关键机制）

`museum.js` 的 `openPlay(id, title)` / `closePlay()`：

- 3D 玩法（bone-float / boss-3d）自己会 `append` 一层 `position:fixed; z-index:400` 的全屏层
  → 馆这边的 `.mu-play` 只做占位（`z-index:350`、`pointer-events:none`）
- 2D 玩法（bone-build）渲染进 host → 馆这边加 `.mu-play-solid`（不透明外壳，`z-index:600`）
- 馆自己在右上角放两颗浮动按钮：`.mu-play-exit`（← 回馆，`z-index:900`）、`.mu-play-snd`（♪ 声音）
- **玩关卡时** `body.mu-play-lock` 会把 `.top/.footer/.app-shell/.mu-bar/.mu-dock/.mu-task/.mu-sum/.mu-hint` 全隐藏

### 3.7 竖屏（2026-10-31 这一轮改的）

手机竖屏横向视野只有约 27°（fov 被 `resize()` 从 42° 顶到 56°，
`aspect 0.462` → 横向半角 ≈ 13.8°）。三处因此必须特殊处理：

1. **造字区题面牌**：横排那版 6.2 单位宽，怎么摆都超出视野。
   `paintBuildSign` 有竖屏分支（只留「第 N/5 / 甲骨字形 / 今字」），
   `fitBuildSign()` 按**当前相机**的横向视野算缩放（最宽 = 视野宽 92%）。
   `resize()` 和 `setArea('build')` 都会调它。
2. **造字区构件**：原来那条 1.84 rad 的弧，最外侧两块在屏幕外 —— 手机上挑不全。
   竖屏改成工作台前的 **2×2 栅格**（`GRID`）。
3. **知识厅机位**：`viewFor('gallery')` 竖屏用 `r 8.6 / y 3.3 / phi 1.48 / theta 0.26`。
   原来的 `r 8.8 / y 2.1 / phi 1.51` 会让镜头贴着骨版环（7.9）外侧不到一米，
   正对的骨版直接填满屏幕。`theta 0.26`（≈15°）把机位让到两块骨版中间。

任务条在窄屏由 CSS 搬到顶部（`@media (max-width: 760px)`），
所以 3D 里那块题面牌必须缩到它下面，别被压住。

### 4.1 第二关 `js/world/bone-float.js`（第一人称）

### 4.5 声音系统（一条开关 / 三条总线）

**一条开关**：馆里顶栏的「声音」和关卡里那颗「♪ 声音」**是同一个状态**，
都读 `App.museumAudio.isOn()`，都订 `App.museumAudio.onChange(cb)` 重画。
存档键 `museumaudio` 只记"用户想不想开"，不代表现在响不响。

**三条总线**：

| 总线 | 文件 | 管什么 | 进馆后 |
|---|---|---|---|
| `App.sound` | `js/core/audio.js` | 站点古筝 BGM + 骨板一击 + 区域氛围 | **挂起**（`suspend()`，不写存档） |
| `App.museumAudio` | `js/museum/museum-audio.js` | 展厅环境音垫 + 3 个提示音 | 受开关控制 |
| `App.battleMusic` | `js/world/battle-music.js` | 战斗音乐，三阶段换 BPM/织体 | 打 Boss 时起 |
| `App.battleSfx` | `js/world/battle-sfx.js` | 12 个战斗事件音 | 打 Boss 时用 |

要点：

- **进出馆**：`scene()` 里 `App.sound.suspend()`；`teardown()` 里
  `App.museumAudio.dispose()` + `battleMusic.dispose()` + `battleSfx.release()` + `App.sound.resume()`。
  少一处就是"离开展馆了还有声音"或"馆里叠着古筝"。
- **进关卡**：`openPlay('boss-3d')` 会 `museumAudio.duck(true)` 把环境音垫压到 28%
  （战斗音乐自己也有低频，两层叠着会糊），`closePlay()` 还原。第二关不 duck。
- **`battleSfx` 与 `battleMusic` 共用一个 AudioContext**，但**不共用推子**：
  `battleMusic.audio()` 返回 `{ctx, out, verb}`，`out` 是独立的 SFX 总线。
  音乐要淡入淡出、胜利后收掉，音效必须随手势立刻响（印章那一下还在收尾之后）。
- **没声音也要能用**：`battleSfx` 每个函数第一句都是 `guard()` →
  `museumAudio.isOn()` 为假就直接 `return false`，不建节点、不抛错。
- **重进馆的"预告"**：存档为开但 AudioContext 还没起时，按钮照实写"声音"（关），
  在 `document` 上挂一次性的 `pointerdown` 把音源补起来。
  ⚠ 这个手势监听必须**跳过声音按钮自己**（见第 7 节第 11 条）。

## 7. 踩过的坑（别重复踩）

1. **缓存**：改 `js/` 或 `css/` 后不升 `?v=`，用户永远看旧版。每次改完都升。
2. **`museum.js` 与 `museum3d.js` 的 ZONES 要同步**（顺序/数量），删「文明序厅」时两边都删。
3. **3D 初始化失败会整体掉平面模式**：典型原因是某个 `addXxx()` 在组还没创建时被调用
   （典藏区那块碑曾写在 `collG = new T.Group()` 之前）。改完一定看 `App.museum.debug().ready`。
4. **`debris()` 必须返回函数**：`S.bursts` 是按 `fn(dt)` 调的，返回对象会每帧抛错、粒子冻结。
5. **`clearWidgets()` 会拆掉一切**：法阵/守阵兽要 `userData.persist = true` 才活得下去
   （否则阶段三羽骨鸟不显示 —— 曾就是这样）。
6. **`stage3d.onPick` 只认 `userData.pickable`**：新加的可点物件必须挂上，
   否则点了没反应（第三关构件骨/笔画都踩过）。
7. **馆内开玩法时的"回馆"**：玩法自带的是 `location.hash = '#/museum'`，
   而 hash 本来就是它、不触发 hashchange → 卡死。必须用馆的 `.mu-play-exit`。
8. **游戏内声音开关被隐藏**：玩关卡时馆顶栏隐藏，`♪ 声音` 按钮是专门为此加的。
9. **bash 里写 python `-c` 长脚本容易引号出错**：超过 1KB 或含中文/引号，就写成 `.py` 文件再跑。
10. **推送**：`origin` 是 https，推不上去；用第 1 节的 SSH 命令，且 `BatchMode=yes`。
11. **`z-index:900` 写在被 `z-index:350` 的父元素里 = 没写**：
    `.mu-play` 自己 `position:fixed; z-index:350`，成了层叠上下文，
    子元素的 900 只在 350 里比，而玩法那层是 400 —— 馆的「← 回馆 / ♪ 声音」
    于是被整个压住，看不见也点不到（`elementFromPoint` 命中的是玩法覆盖层）。
    现在这两颗**挂在 `document.body` 上**，别改回去。定位因此下移到 `top:58px`，
    避开玩法自己的顶栏。
12. **`pointerdown` 会抢在 `click` 前面**：补挂声音的那次手势监听如果在按钮自己身上也触发，
    就成了"先替你打开、再被 click 关掉"，用户点一下等于没点（甚至反了）。
    监听里必须 `closest('.mu-btn-audio, .mu-play-snd')` 跳过声音按钮。
13. **玩法自带的「回馆」写法不统一**：第三关是 `<button>`，第二关是 `<div>`。
    只给 `button/a` 改 `onclick` 的话，第二关那颗 `div` 从来没被接管过，
    点了没反应（它把 `location.hash` 设成 `'#/museum'`，而 hash 本来就是它）。
    现在改成在 `document` 上**事件委托**，谁的文字是「回馆」都算。
14. **按钮文字要和真实状态一致**：早期 `paintAudio(App.museumAudio.preferOn())`
    画的是存档，不是现在响不响 —— 存档"开"但 AudioContext 还没起时，
    按钮写着"声音 开"，点下去没变化。读状态就一律读 `isOn()`。
15. **模型物件挂上了 `userData.kind` 不等于点得开**：`pickAt` 里必须有一个
    对应 `kind` 的分支往下 `send({type: ...})`。龟甲就是这样 —— hover 有手型光标、
    但点下去什么也不发生，因为 `pickAt` 里压根没有 `plastron` 分支（2026-10-31 补上）。
    新加可点物件，**记得两头都改**：`userData` + `pickAt` 分支 + `museum.js` 的 hit 分发。
16. **`pickables` 才是馆里的可点集合**：馆用自己的射线列表，不看 `userData.pickable`
    （那个是 `stage3d` 给玩法层用的约定）。所以新物件要 `pickables.push(mesh)`。
17. **`getModel()` 的初始化顺序**：`MODELS / modelCache / modelState` 是 `var`，
    在展厅那一段之后才赋值。在它们之前调用 `getModel` 会拿到 undefined 并抛错 ——
    用 `setTimeout(fn, 0)` 推到本轮同步代码跑完再取。
18. **透明 `Mesh` 当点击热区**：三足之间是空的，光标从缝里过去会点不到，
    所以鼎加了一个 `opacity:0` 的圆柱热区。做了这种热区就不用再给每个零件挂 `userData`。
19. **算距离一定要用世界坐标**：`buildG` 挂在 `z = ANX_Z`（-360）上。
    题面牌的适配缩放一开始拿局部坐标 `(0, y, -2.5)` 去和 `camera.position` 比距离，
    算出来是 360 米外 → 缩放永远是 1 → 竖屏那块牌子怎么都不肯变小。
    要用 `getWorldPosition(v)`。
20. **`camera.aspect` 决定一切布局**：题面牌尺寸、构件摆法都按它分支，
    所以 Anything "按屏幕算" 的东西都要在 `resize()` 里再算一遍，
    而不是建场景时算一次就完。
